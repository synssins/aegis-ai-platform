## 1. Request Field Coverage

### 1.1 Premature Loop Termination and Single-Turn Scope in Message Collection
- **Severity**: High
- **Title**: Premature Loop Termination and Multi-Turn Omission in [`collect_request_text`]
- **Mechanism**: 
  In [`collect_request_text`], the loop traverses `reversed(data.get("messages") or [])`. 
  1. The loop issues a `break` as soon as it encounters a message that is not `role == "tool"`. If the last message is an `assistant` turn (such as an assistant prefill attack or few-shot demonstration) or a `system` turn, it matches neither `"tool"` nor `"user"`, hitting `break` immediately. Consequently, `texts` is empty, and [`async_pre_call_hook`] exits early on line 314 (`if not texts: return data`), bypassing both tripwires and classifier checks.
  2. If the last message is a `user` turn, it breaks immediately after that turn. In multi-turn dialogues, earlier user turns, system messages, and assistant context are ignored. Disallowed instructions split across conversational turns or framed in earlier setup prompts are never inspected.
- **Fix**: 
  Collect all conversational roles relevant to model steering (`system`, `developer`, `user`, `assistant`, `tool`). When constructing context for the safety classifier, assemble the conversation in chronological order up to the latest prompt:
  ```python
  def collect_request_text(data: dict) -> list[str]:
      texts: list[str] = []
      for m in data.get("messages") or []:
          if isinstance(m, dict):
              content = _content_to_text(m.get("content"))
              if content:
                  texts.append(f"{m.get('role', 'user')}: {content}")
      for key in ("prompt", "input", "system"):
          v = data.get(key)
          if isinstance(v, list):
              texts.extend(str(x) for x in v if x)
          elif v:
              texts.append(str(v))
      return texts
  ```

### 1.2 Uninspected Top-Level System Instructions and Tool Schema Injections
- **Severity**: Medium
- **Title**: Missing Coverage for Top-Level System Arguments and Tool Schemas
- **Mechanism**: 
  In LiteLLM, model calls targeting Anthropic, Cohere, or Google often pass system prompts via a top-level `system` key in `data`. Furthermore, attackers can embed jailbreaks or instructions within function/tool descriptions (`data.get("tools")` or `data.get("functions")`). - **Fix**:

## 2. Normalisation Gaps

### 2.1 Incomplete Unicode Normalization (Diacritics, Confusables, and Bidi Controls)
- **Severity**: Medium
- **Title**: Tripwire Bypass via Diacritics, Homoglyphs, and Unfiltered Bidi Controls in [`normalise`]
- **Mechanism**: 
  [`normalise`] uses `unicodedata.normalize("NFKC", text)` and a narrow character class in [`ZERO_WIDTH_RE`].
  1. **Combining Diacritical Marks**: NFKC does not strip combining diacritics (Unicode range `U+0300`-`U+036F`). Interspersing combining accents between ASCII letters breaks word boundaries (`\b`) and literal regex tokens while remaining intelligible to the downstream LLM.
  2. **Cross-Script Homoglyphs**: Confusables (e.g., Cyrillic or Greek characters identical in appearance to Latin characters) are not mapped to Latin equivalents by NFKC.
  3. **Directional & Formatting Controls**: Bidirectional overrides (`U+202A`-`U+202E`, `U+2066`-`U+2069`) and variation selectors (`U+FE00`-`U+FE0F`) are omitted from [`ZERO_WIDTH_RE`].
- **Fix**: 
  Strip combining diacritics using Unicode decomposition (`NFD`), strip all Unicode formatting/control characters (category `Cf`), and apply confusable mapping:
  ```python
  import unicodedata

  def normalise(text: str) -> str:
      text = unicodedata.normalize("NFD", text)
      # Strip combining marks (Mn) and formatting controls (Cf)
      text = "".join(ch for ch in text if unicodedata.category(ch) not in ("Mn", "Cf"))
      text = unicodedata.normalize("NFKC", text)
      return WS_RE.sub(" ", text).lower()[:MAX_SCAN_CHARS]
  ```

### 2.2 Base64 Extraction Deficiencies and URL-Safe Base64 Evasion
- **Severity**: Medium
- **Title**: Base64 Pattern Strictness and Classifier Omission in [`_decoded_b64_fragments`]
- **Mechanism**: 
  1. [`B64_RUN_RE`] matches `[A-Za-z0-9+/]{24,}={0,2}`. It omits URL-safe Base64 alphabets (`-` and `_`). Any payload encoded with URL-safe Base64 is bypassed.
  2. The regex requires a continuous sequence of at least 24 characters. Embedded whitespace, carriage returns, or padding variations defeat the regex.
  3. Decoded fragments are only passed to the regex tripwires in [`scan`] and [`scan_despaced`]. Decoded text is never passed to [`classify_request`], allowing encoded prompts to bypass semantic classification.
- **Fix**: 
  Expand Base64 detection to handle URL-safe characters and whitespace stripping, decode valid fragments, and append decoded fragments to the text list evaluated by [`classify_request`].

### 2.3 Delimiter Evasion in Despaced Tripwires
- **Severity**: Low
- **Title**: Incomplete Punctuation Stripping in [`DESPACE_RE`]
- **Mechanism**: 
  [`DESPACE_RE`] is defined as `[\s_\[\]\-.*]+`. If an attacker separates characters using punctuation outside this set (such as `/`, `\`, `|`, `~`, `,`, `!`, `+`, `#`), [`scan_despaced`] fails to collapse the tokens, evading despaced regex matching.
- **Fix**: 
  Remove all non-alphanumeric characters for despaced matching:
  ```python
  NON_ALPHANUM_RE = re.compile(r"[^a-z0-9]+")
  ```

## 3. Streaming Path

### 3.1 Uninspected Streaming Tool Calls Leak Directly to Client
- **Severity**: High
- **Title**: Complete Bypass of Safety Gate for Streaming Tool Calls in [`async_post_call_streaming_iterator_hook`]
- **Mechanism**: 
  Line 365 reconstructs output text via:
  ```python
  text = "".join((getattr(c.choices[0].delta, "content", None) or "") for c in buffered if getattr(c, "choices", None))
  ```
  When the model generates tool calls in streaming mode, the payload resides in `delta.tool_calls` (containing function names and streaming argument fragments), while `delta.content` is `None` or `""`.
  As a result, `text` is empty. Line 293 in [`classify_output`] immediately returns `False, []` for empty text. The hook deems the output safe and flushes all buffered chunks (lines 373-375) directly to the client without classification.
- **Fix**: 
  Accumulate `delta.tool_calls` across streaming chunks and concatenate tool names and arguments into the text submitted to [`classify_output`].

### 3.2 Missing Lexical Tripwire Inspection on Streaming Outputs
- **Severity**: Medium
- **Title**: Absence of Lexical Tripwire Enforcement in Streaming Responses
- **Mechanism**: 
  [`async_post_call_streaming_iterator_hook`] evaluates model outputs solely via [`classify_output`]. It does not run [`scan`] or [`scan_despaced`]. If the safety classifier fails to trigger on content explicitly forbidden by tripwire patterns, the streaming path allows the content through.
- **Fix**: 
  Run [`scan`] and [`scan_despaced`] against the reconstructed streaming text prior to releasing chunks.

### 3.3 Unbounded In-Memory Stream Buffering (Denial of Service)
- **Severity**: Medium
- **Title**: Unbounded Stream Accumulation Leading to Memory Exhaustion
- **Mechanism**: 
  In [`async_post_call_streaming_iterator_hook`], lines 360-362 loop over `response` and append every chunk to `buffered` without enforcing a maximum token, byte, or chunk limit. An attacker prompting the model to generate extremely long outputs can exhaust host memory across concurrent connections.
- **Fix**: 
  Enforce a hard ceiling on cumulative buffered bytes or chunk count. If exceeded, terminate the upstream stream, audit the threshold violation, and withhold the response.

### 3.4 Unhandled Empty Choices Causing `IndexError` in Streaming Hook
- **Severity**: Low
- **Title**: Unhandled Empty `choices` List Causing Uncaught `IndexError`
- **Mechanism**: 
  Line 365 performs `getattr(c.choices[0].delta, "content", None)`. In LiteLLM and OpenAI-compatible streaming streams, trailing usage chunks or metadata chunks frequently contain an empty `choices: []` list. Accessing `c.choices[0]` raises an unhandled `IndexError`, crashing the generator mid-stream.
- **Fix**: 
  Guard chunk choice indexing:
  ```python
  text = "".join(
      (getattr(c.choices[0].delta, "content", None) or "")
      for c in buffered
      if getattr(c, "choices", None) and len(c.choices) > 0
  )
  ```

## 4. Tool-Call Path

### 4.1 Unconditional Fail-Open on Tool-Call Extraction Exceptions
- **Severity**: High
- **Title**: Fail-Open Exception Catch in [`async_post_call_success_hook`]
- **Mechanism**: 
  Lines 337-345 in [`async_post_call_success_hook`]:
  ```python
  try:
      outputs = []
      for c in getattr(response, "choices", []) or []:
          outputs.append(_content_to_text(getattr(c.message, "content", None)))
          for tc in getattr(c.message, "tool_calls", None) or []:
              fn = getattr(tc, "function", None)
              outputs.append(f"{getattr(fn, 'name', '')} {getattr(fn, 'arguments', '')}")
  except Exception:  # noqa: BLE001
      return response
  ```
  If `response` uses dictionary indexing (common across certain LiteLLM adapter paths), or if `tool_calls` contains unexpected object structures, an unhandled exception is caught by `except Exception:` and executes `return response`. This completely bypasses post-call classification and outputs the unfiltered response to the client.
- **Fix**: 
  Adhere strictly to fail-closed principles:
  ```python
  except Exception as e:
      audit("post_call", "extraction_failure", str(e)[:200], data, user_api_key_dict)
      _refuse(500, "safety_processing_error", "Error evaluating response safety (fail-closed).")
  ```

## 5. Classifier Chunking

### 5.1 Arbitrary Boundary Slicing without Overlap
- **Severity**: High
- **Title**: Semantic Boundary Fragmentation via Non-Overlapping Slices in [`_chunks`]
- **Mechanism**: 
  [`_chunks`] performs naive string slicing: `[text[i:i + n] for i in range(0, len(text), n)]`.
  If an adversarial payload or disallowed phrase spans across the boundary (e.g., bytes 5,980 through 6,020 when `chunk_chars` is 6,000), neither chunk contains sufficient semantic context to trigger the classifier, resulting in false negatives.
- **Fix**: 
  Implement sliding-window chunking with an overlap margin (e.g., 500-1,000 characters) or split on sentence/paragraph boundaries.

### 5.2 Context Truncation and Loss of Turn Association
- **Severity**: Medium
- **Title**: Context Truncation and Isolated Turn Classification
- **Mechanism**: 
  1. In [`classify_request`], all collected texts are joined with `\n` and chunked. Each chunk is submitted to Llama Guard in isolation (`[{"role": "user", "content": ch}]`). Conversational context establishing intent (e.g., roleplay or adversarial framing established in earlier paragraphs) is lost.
  2. In [`classify_output`], line 298 truncates the prompt context to the first `chunk_chars` characters (`request_text[:6000]`). If the critical request instructions were positioned at the end of a long prompt, the classifier evaluates the assistant output against an irrelevant prompt prefix.
- **Fix**: 
  For output classification, prioritize the most recent user turn for `user_ctx`. If the prompt exceeds `chunk_chars`, preserve both the initial system framing and the trailing user instruction rather than a blind prefix slice.

### 5.3 Sequential Classifier Latency Exhaustion (Denial of Service)
- **Severity**: High
- **Title**: Sequential Backend Classifier Invocations Enabling Resource Exhaustion DoS
- **Mechanism**: 
  [`classify_request`] and [`classify_output`] iterate through chunks sequentially:
  ```python
  for ch in chunks:
      unsafe, cats = await _guard_call(...)
  ```
  With `max_chunks = 200` and `timeout = 60`, an adversary submitting large inputs (e.g., 1.2 MB of benign text followed by a violation) forces up to 200 serialized HTTP requests to the Ollama backend. This can tie up proxy workers and Ollama inference queues for hundreds of seconds per request.
- **Fix**: 
  Set a lower, realistic `max_chunks` default (e.g., 5-10 chunks), reject inputs exceeding safe limits early, and evaluate chunks concurrently using `asyncio.gather` with a bounded semaphore.

## 6. Policy Reload & Concurrency

### 6.1 State Poisoning and Default Fallback Lock-in on Non-Atomic Writes
- **Severity**: High
- **Title**: Premature `st_mtime` Update Causing Silent Fallback and Policy Lock-in
- **Mechanism**: 
  In [`Policy.reload`]:
  ```python
  m = os.stat(POLICY_PATH).st_mtime
  if m == self._mtime:
      return
  self._mtime = m
  data = copy.deepcopy(DEFAULT_POLICY)
  if m is not None:
      try:
          with open(POLICY_PATH, encoding="utf-8") as f:
              loaded = json.load(f)
  ```
  `self._mtime = m` is assigned *before* reading and parsing the file.
  If the policy file is updated non-atomically (written in-place rather than via atomic rename `os.replace`), `json.load(f)` reads a partial file and throws a `JSONDecodeError`.
  The exception is caught on line 96, and the policy reverts to [`DEFAULT_POLICY`].
  Crucially, because `self._mtime` was already updated to the new timestamp, subsequent calls observe `m == self._mtime` and immediately return. All custom blocked categories and extra tripwires are permanently lost until the file's modification time changes again.
- **Fix**: 
  Only update `self._mtime` after successfully reading and parsing the file. If reading fails, keep the previous valid policy rather than reverting to defaults:
  ```python
  def reload(self) -> None:
      try:
          m = os.stat(POLICY_PATH).st_mtime
      except OSError:
          return
      if m == self._mtime:
          return
      try:
          with open(POLICY_PATH, encoding="utf-8") as f:
              loaded = json.load(f)
          # Process loaded data into new_data, new_pats...
          self.data = new_data
          self.extra_re = new_pats
          self._mtime = m
      except Exception as e:
          log.error("Failed to reload policy (%s); retaining active policy", e)
  ```

### 6.2 Regular Expression Denial of Service (ReDoS) via Extra Tripwires
- **Severity**: High
- **Title**: Unvalidated Regex Compilation Permitting Catastrophic Backtracking
- **Mechanism**: 
  Lines 101-105 compile patterns from `data["tripwires"].get("extra_patterns", [])` directly using `re.compile(p, re.IGNORECASE | re.DOTALL)`.
  If an administrator or policy updater configures an extra tripwire pattern subject to catastrophic backtracking (e.g., nested quantifiers like `(a+)+`), executing [`scan`] over inputs up to [`MAX_SCAN_CHARS`] (2,000,000 characters) will lock the Python process thread indefinitely.
- **Fix**: 
  Enforce linear-time regular expressions using the `regex` module or Google's `re2` library, or execute regex searches within a bounded worker thread or timeout.

### 6.3 Thread-Unsafe Reload and Per-Request Filesystem Overhead
- **Severity**: Low
- **Title**: Non-Thread-Safe Policy Mutation and I/O Overhead on Every Call
- **Mechanism**: 
  `POLICY.reload()` is invoked on every single pre-call, post-call, and streaming hook execution. Under high concurrency across multiple threads/tasks, calling `os.stat` repeatedly creates unnecessary I/O contention. Furthermore, modifying `self.data` and `self.extra_re` in-place without synchronization can expose concurrent requests to inconsistent states during reload.
- **Fix**: 
  Cache policy reload checks using an interval timer (e.g., check `st_mtime` at most once every 5 seconds) and protect updates with an `asyncio.Lock` or `threading.Lock`.

## 7. Error Handling & Classifier Response Parsing

### 7.1 Permissive Verdict Prefix Matching in Classifier Hook
- **Severity**: Medium
- **Title**: Ambiguous Prefix Matching (`verdict.startswith("safe")`) in [`_guard_call`]
- **Mechanism**: 
  Line 263 checks:
  ```python
  if verdict.startswith("safe"):
  ```

  If Llama Guard or an alternative backend model returns conversational preambles or nuanced explanations that happen to begin with "safe" (e.g., `"safe handling requires..."` or `"safety considerations: unsafe"`), the condition evaluates to `True`, categorizing the content as benign and allowing it through.
- **Fix**:

  ```python
  lines = [line.strip() for line in verdict.splitlines() if line.strip()]
  if not lines:
      raise GuardUnavailable("empty verdict")
  if lines[0] == "safe":
      return False, []
  if lines[0] == "unsafe":
      cats = [c.upper() for c in re.findall(r"s\d{1,2}", verdict)]
      return True, cats or ["UNSPECIFIED"]
  raise GuardUnavailable(f"Unexpected guard verdict format: {verdict[:50]}")
  ```

## 8. Audit Logging & Observability

### 8.1 Attribution Loss via Attribute vs. Dictionary Access Failure
- **Severity**: Medium
- **Title**: Silent Attribution Loss in [`audit`]
- **Mechanism**: 
  Line 228 extracts the key alias using:
  ```python
  getattr(key_dict, "key_alias", None) or getattr(key_dict, "user_id", None)
  ```
  In LiteLLM, `user_api_key_dict` is frequently passed to hooks as a plain Python `dict` rather than an object. When a `dict` is passed, `getattr()` returns `None`. The audit log records `"key_alias": null` for all veto events, preventing security operators from attributing violations to specific API keys or users.
- **Fix**: 
  Support both object attribute and dictionary key extraction:
  ```python
  def _get_key_alias(key_dict: Any) -> str | None:
      if isinstance(key_dict, dict):
          return key_dict.get("key_alias") or key_dict.get("user_id")
      return getattr(key_dict, "key_alias", None) or getattr(key_dict, "user_id", None)
  ```

### 8.2 Event Loop Blocking and Uncontrolled Disk Growth
- **Severity**: Medium
- **Title**: Synchronous Disk I/O Blocking Async Event Loop and Disk Exhaustion Risk
- **Mechanism**: 
  1. [`audit`] executes synchronous file operations (`os.makedirs` and `open(..., "a").write(...)`) directly inside the async request path. On slow, congested, or network-attached filesystems (e.g., NFS), this blocks the Python asyncio event loop, causing latency spikes across all concurrent requests.
  2. [`AUDIT_PATH`] writes continuously to an unbounded `.jsonl` file without size checks or log rotation, creating a disk exhaustion DoS vector under automated attacks.
- **Fix**: 
  Offload audit logging to a background worker queue or use non-blocking I/O (`aiofiles` / `asyncio.to_thread`), and configure log rotation (`RotatingFileHandler`).
